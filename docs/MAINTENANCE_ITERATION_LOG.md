# Maintenance Iteration Log

Registro interno recurrente para mejoras de alto valor y bajo riesgo. Cada iteración debe ser pequeña, verificable y cerrarse con evidencia de checks.

## Criterios de Uso

- Registrar solo mejoras que reduzcan riesgo real de estabilidad, seguridad, mantenibilidad o escalabilidad.
- Evitar refactors cosméticos sin señal operacional.
- Preferir guardrails, seams y documentación mínima antes que capas nuevas.
- Cerrar cada iteración con comandos ejecutados y próximos pasos concretos.

## Bloques Sugeridos

### Bloque A: Bootstrap liviano y explícito

- Objetivo: sacar `vendor-excel-core` del `entry` principal si hoy sigue entrando por un helper compartido, side effect o import de conveniencia.
- Alcance: revisar solo el camino de bootstrap, loaders compartidos y entrypoints de Excel ya existentes.
- Guardrail: no crear una nueva capa de abstracción; resolver con lazy load, aislamiento de helper o separación de chunk si el corte es claro.
- Criterio de cierre: el `entry` deja de importar `vendor-excel-core`, `npm run build` y `npm run check:bundle-budget` quedan verdes.
- Valor: reduce peso inicial y hace más predecible el shell de arranque.

### Bloque B: Shared chunks con costo real de navegación

- Objetivo: revisar el peso de `index-*` y `CensusRegisterContent-*` para identificar imports de alto fan-in que todavía mezclan shell con features pesadas.
- Alcance: modales, viewers, exportadores o registries que ya estén en el límite y tengan una frontera funcional clara.
- Guardrail: dividir solo donde haya una frontera de uso real; evitar micro-chunks por estética.
- Criterio de cierre: bajar el peso de uno de esos chunks sin aumentar complejidad accidental ni romper preload o lazy paths.
- Valor: mejora mantenibilidad y tiempo de carga en rutas de uso frecuente.

### Bloque C: Guardrails de bundle orientados a decisiones

- Objetivo: convertir los hotspots actuales de bundle en una señal operacional fácil de leer dentro del release gate.
- Alcance: reportar 3 a 5 chunks estratégicos con estado `ok`, `near-limit` o `over-limit`.
- Guardrail: no montar una plataforma nueva; extender el checker y los reportes que ya existen.
- Criterio de cierre: el scorecard o reporte deja claro qué chunks son los próximos candidatos sin inspección manual del build.
- Valor: evita que el aprendizaje de estas iteraciones se pierda entre builds.

### Bloque D: Smoke tests de carga diferida crítica

- Objetivo: cubrir con 1 o 2 pruebas focalizadas los caminos lazy que más tocamos en Excel y PDF para evitar regresiones silenciosas.
- Alcance: loaders compartidos o servicios que ahora dependen de import dinámico y caché.
- Guardrail: pruebas chicas y deterministas; no abrir una campaña E2E amplia.
- Criterio de cierre: los caminos lazy críticos fallan rápido si alguien reintroduce imports estáticos pesados o rompe el loader.
- Valor: protege el trabajo de performance con muy poco costo de mantenimiento.

### Bloque E: Hotspots de alto fan-in sin refactor cosmético

- Objetivo: bajar el riesgo de cambio en 1 hotspot real de alto fan-in por iteración corta.
- Alcance: contratos, contextos o registries compartidos que ya aparecieron en reportes arquitectónicos.
- Guardrail: extraer solo cuando el cambio tenga un beneficio inmediato de lectura, test o aislamiento; no purificar por estilo.
- Criterio de cierre: menos acoplamiento visible o menor superficie importada en un hotspot puntual, con tests focalizados verdes.
- Valor: sostiene escalabilidad futura sin disparar una re-arquitectura.

### Bloque F: Higiene operativa y frescura de reportes

- Objetivo: mantener alineados reportes, scorecards y documentación de guardrails con el commit real y los checks actuales.
- Alcance: scripts y docs de release readiness, bundle budgets y maintenance log.
- Guardrail: cambios documentales o de checker solamente; nada de flujos nuevos para el equipo.
- Criterio de cierre: cualquier desalineación importante queda visible antes de release y el backlog iterativo sigue vigente.
- Valor: convierte deuda difusa en trabajo pequeño, verificable y recurrente.
